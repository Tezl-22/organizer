# Проєктні дані органайзера (для UML-діаграм у пояснювальній записці)

## 1. Архітектура

- Тип: клієнт-серверний вебзастосунок, багатошарова архітектура (варіант MVC для Flask):
  - Представлення (View) — шаблони Jinja2 у `templates/`, стилі `static/style.css`;
  - Контролер — маршрути Flask у `app.py` (обробка запитів, перевірка форм);
  - Модель / доступ до даних — `db.py` (класи-репозиторії, SQL-запити до SQLite), `month_calendar.py` (логіка місячної сітки).
- Клієнт: браузер (HTML-форми, без JS-фреймворків; лише `confirm()` перед видаленням).
- Сервер: Python 3 + Flask 3.1.3; СУБД SQLite (файл `instance/organizer.db`, модуль `sqlite3`).
- Формати даних: дата `YYYY-MM-DD`, дата-час `YYYY-MM-DD HH:MM` (текстові поля SQLite; поле форми `datetime-local` надсилає `YYYY-MM-DDTHH:MM`, яке перетворюється перед збереженням).

## 2. Модель даних (ER)

Три незалежні сутності (зв'язків між таблицями немає — задачі й нагадування поєднуються лише на рівні відображення в календарі за датою).

| Сутність  | Поле        | Тип     | Обмеження / примітка |
|-----------|-------------|---------|----------------------|
| tasks     | id          | INTEGER | PK, AUTOINCREMENT |
|           | title       | TEXT    | NOT NULL, ≤ 200 символів (перевірка в застосунку) |
|           | description | TEXT    | NOT NULL, DEFAULT '' |
|           | priority    | INTEGER | NOT NULL, DEFAULT 2, CHECK IN (1,2,3): 1 – низький, 2 – середній, 3 – високий |
|           | due_date    | TEXT    | NULL або YYYY-MM-DD, індекс idx_tasks_due |
|           | is_done     | INTEGER | NOT NULL, DEFAULT 0, CHECK IN (0,1) |
|           | created_at  | TEXT    | DEFAULT поточний час |
| notes     | id          | INTEGER | PK, AUTOINCREMENT |
|           | title       | TEXT    | NOT NULL, ≤ 200 символів |
|           | content     | TEXT    | NOT NULL, DEFAULT '' |
|           | created_at  | TEXT    | DEFAULT поточний час |
|           | updated_at  | TEXT    | оновлюється під час редагування |
| reminders | id          | INTEGER | PK, AUTOINCREMENT |
|           | title       | TEXT    | NOT NULL, ≤ 200 символів |
|           | description | TEXT    | NOT NULL, DEFAULT '' |
|           | remind_at   | TEXT    | NOT NULL, YYYY-MM-DD HH:MM, індекс idx_reminders_at |
|           | created_at  | TEXT    | DEFAULT поточний час |

| FR-11 | Календар місяця із задачами (за терміном) і нагадуваннями | `/calendar`, `CalendarMonth`, `*.for_period` |

| FR-13 | Перевірка введених даних з повідомленнями українською | `validate_task`, `validate_note`, `validate_reminder` |

Нефункціональні вимоги (пропозиція з вимірюваними значеннями):
- NFR-01 Продуктивність: відкриття будь-якої сторінки ≤ 1 с при базі до 10 000 записів (локальний сервер).
- NFR-02 Надійність: усі SQL-запити параметризовані; некоректні дані не потрапляють у БД (перевірка + CHECK-обмеження).
- NFR-03 Зручність: усі повідомлення та елементи інтерфейсу українською; будь-яка дія виконується не більше ніж за 3 кліки з головного меню.
- NFR-04 Сумісність: коректна робота в Chrome/Firefox/Edge останніх версій при ширині вікна від 1024 px.
- NFR-05 Переносимість: запуск на Windows/Linux/macOS з Python ≥ 3.10 однією командою після `pip install -r requirements.txt`.
- NFR-06 Супровідність: покриття функціональних вимог автоматичними тестами pytest (21 тест), код за PEP 8.

## 6. Класи та модулі (для діаграми класів)

| Клас / модуль | Атрибути | Методи | Відповідальність |
|---------------|----------|--------|------------------|
| `BaseRepository` (db.py) | `table: str` | `get(item_id)`, `delete(item_id)` | Спільні операції з таблицею за id |
| `TaskRepository` (db.py) | `table = "tasks"` | `list(status, priority)`, `create(...)`, `update(...)`, `toggle(task_id)`, `for_period(start, end)` | Запити до таблиці задач |
| `NoteRepository` (db.py) | `table = "notes"` | `list(search)`, `create(title, content)`, `update(...)` | Запити до таблиці нотаток, пошук |
| `ReminderRepository` (db.py) | `table = "reminders"` | `list()`, `create(...)`, `update(...)`, `overdue(now)`, `upcoming(now, until)`, `for_period(start, end)` | Запити до таблиці нагадувань, вибірка за часом |
| `CalendarMonth` (month_calendar.py) | `year`, `month`, `weeks: list[list[date]]` | `title`, `first_day`, `last_day` (властивості), `prev()`, `next()`, `is_current_month(day)` | Побудова сітки місяця (тижні з понеділка) |
| Сутності `Task`, `Note`, `Reminder` | поля відповідних таблиць (див. п. 2) | — | Записи БД (`sqlite3.Row`), якими оперують репозиторії |
| модуль `app.py` | `PRIORITIES`, `DATETIME_FORMAT`, `UPCOMING_DAYS` | `create_app()`, `validate_task/note/reminder()`, `parse_date()`, `parse_datetime()`, маршрути | Контролер: маршрути, валідація, банер |
| модуль `db.py` | — | `get_db()`, `close_db()`, `init_db()` | Підключення до SQLite (одне на запит), створення схеми |

Відношення:
- Наслідування: `TaskRepository`, `NoteRepository`, `ReminderRepository` → `BaseRepository`.
- Асоціація (1 → *): кожен репозиторій керує записами своєї сутності (`TaskRepository` – `Task` тощо).
- Агрегація: сторінка календаря (`calendar_view`) поєднує `CalendarMonth` із задачами та нагадуваннями, згрупованими за датою.
- Залежність: `app.py` використовує `db.tasks`, `db.notes`, `db.reminders` (об'єкти-репозиторії) та `CalendarMonth`.

## 7. Діаграма послідовностей «Створення задачі»

1. Користувач → Браузер: заповнює форму «Нова задача», натискає «Зберегти».
2. Браузер → Flask (`task_new`): POST `/tasks/new` (title, description, priority, due_date).
3. `task_new` → `validate_task(form)`: перевірка назви, пріоритету, дати.
4. Якщо є помилки: `task_new` → Браузер: форма з переліком помилок (код 400), дані не зберігаються.
5. Якщо помилок немає: `task_new` → `TaskRepository.create(...)` → SQLite: `INSERT INTO tasks ...`, `COMMIT`.
6. `task_new` → Браузер: переадресація на `/tasks` із повідомленням «Задачу додано.».
7. Браузер → `task_list` → `TaskRepository.list()` → SQLite `SELECT` → шаблон `tasks.html`.

## 8. Діаграма діяльності «Показ нагадувань»

Початок → отримати запит на будь-яку сторінку → визначити поточний час `now` → вибрати нагадування з `remind_at < now` (прострочені) → вибрати нагадування в проміжку [now; now + 24 год] → [є прострочені?] так: показати червоний банер з кількістю → [є найближчі?] так: показати жовтий банер для кожного → відобразити вміст сторінки → Кінець.
На сторінці «Нагадування» додатково: прострочені (червоне тло), найближчі 7 днів, усі.
